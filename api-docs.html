APS_Server v0.0.1

Base URL: http://localhost:8080/

Реактивный файловый сервер (облачное хранилище) на Spring Boot 4.0.5 (WebFlux) и Java 21. Предоставляет функциональность, аналогичную Google Drive / Dropbox: загрузку, скачивание, организацию файлов по папкам, корзину (soft-delete) и управление аккаунтами.

Стек технологий:

  • Spring WebFlux — реактивный, неблокирующий стек
  • Spring Security + JWT (jjwt 0.13.0, HMAC-SHA), stateless
  • Spring Data R2DBC + PostgreSQL (схема filedb)
  • Хранение файлов: файловая система (storage.path = ./uploads)
  • Квота на пользователя: 10 ГБ (storage.quota)

Концепция корзины: удаление файлов и папок — soft-delete (перемещение в bin_<userId>). Жёсткое удаление — purge (физическое уничтожение).

Authorize

Схема: Bearer JWT Token  |  Header: Authorization: Bearer <token>  |  TTL: 24h

Публичные маршруты: /auth/** (permitAll). /admin/** требует ROLE_ADMIN. Все остальные — валидный JWT. Payload JWT содержит sub (username) и role (ROLE_USER / ROLE_ADMIN). Ответы 401/403 отдаются без WWW-Authenticate: Basic, чтобы SPA могла обработать ошибку без браузерного диалога.

auth Регистрация, аутентификация пользователей и администраторов

POST /auth/register Регистрация нового пользователя
Регистрация нового пользователя. Сохраняет запись в таблицу users с ролью USER, автоматически создаёт корневую папку (root_<userId>) и папку корзины (bin_<userId>) на диске и в БД. Возвращает JWT токен.

{
  "username": "string",
  "password": "string"
}

Responses

500Internal Server Error (например, username занят)
POST /auth/login Аутентификация пользователя
Унифицированная аутентификация. Проверяет логин/пароль через ReactiveAuthenticationManager (BCrypt) и принимает credentials как обычных пользователей, так и администраторов (UserDataService ищет принципала и в users, и в admins). В выданном JWT присутствует строка role (ROLE_USER / ROLE_ADMIN) — клиент использует её для маршрутизации после входа.

POST /auth/register/admin Регистрация нового администратора 🔒 ADMIN
Создание нового администратора. Требует JWT с ролью ADMIN — security-фильтр отклонит запрос без неё (403). Сохраняет запись в таблицу admins с ролью ADMIN; корневые папки не создаются; возвращает JWT токен для нового админа.

Первый администратор не может быть создан этим эндпоинтом (chicken-and-egg). Вместо этого выставьте переменные окружения ADMIN_BOOTSTRAP_USERNAME и ADMIN_BOOTSTRAP_PASSWORD (например, в .env) — AdminBootstrap при старте приложения идемпотентно создаст эту учётную запись, если её ещё нет. После этого ротировать пароли уже через данный эндпоинт.
